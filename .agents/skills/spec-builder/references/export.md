# 导出指南

spec.md 写到一定完成度后，按下面的规则调用 open-cowork 已经内置的 skill 完成导出。**不要自己写新的导出脚本**——复用现有 skill 是这个架构的设计意图。

---

## 导出前检查

无论导出哪种格式，先确认：

1. 至少 60% 的非 `skipped` 章节状态为 `confirmed`
2. §1（项目概述）、§3（目标与非目标）必须 `confirmed`——这两节是文档的"脸面"
3. 用户明确同意当前版本可以导出（不要自作主张）

如果完成度不够，先告知用户：

> "目前覆盖度 45%。导出 docx 不会有问题，但 §6 §7 还是空的，发出去可能被反复追问。要先补完还是直接导？"

---

## 导出到 Word (docx)

**适用场景**：发给老板、归档、走流程评审。

**调用**：`docx` skill。

**传入**：

- 输入文件：工作区根目录的 `spec.md`
- 输出路径：`spec.docx`（同目录）
- 样式要求："使用标准 PRD 样式：标题加粗、表格带边框、代码块等宽字体"

**导出后处理**：

- 提醒用户：「`spec.docx` 已生成，可在文件管理器中右键打开」
- 不要替用户重命名带版本号——用户自己加 `v0.1 / v1.0`

---

## 导出到 PDF

**适用场景**：正式归档、对外发送（如客户、合作方）。

**两条路径**，二选一：

### 路径 A：spec.md → docx → pdf（推荐）

1. 先按"导出到 Word"生成 `spec.docx`
2. 再调用 `pdf` skill 把 `spec.docx` 转为 `spec.pdf`

优点：保留 Word 格式（更接近用户期待）；可同时拿到 docx 和 pdf 两份。

### 路径 B：spec.md 直接 → pdf

- 调用 `pdf` skill，直接渲染 Markdown 到 PDF。
- 用于不需要 Word 中间产物的场景。

---

## 导出到 PPT 大纲（pptx）

**适用场景**：评审会、立项汇报、跟老板对齐方向。

**关键差异**：**不要把 spec.md 整份倒进去**——一份 PRD 有 8 节、几十条目，做成 PPT 就是 30+ 页没人想看。

**评审 PPT 黄金结构（8-12 页）**：

| 页   | 内容                                     | 取自          |
| ---- | ---------------------------------------- | ------------- |
| 1    | 封面：项目名 + 一句话定位                | §1            |
| 2    | 背景与机会                               | §2            |
| 3    | 目标（3-5 条）                           | §3.1          |
| 4    | **非目标**（明确不做什么）               | §3.2          |
| 5-6  | 关键用户故事（选 3 条最代表性的）        | §4            |
| 7    | 功能蓝图（模块图 / 列表）                | §5 各模块标题 |
| 8    | 里程碑路线图                             | §8.1          |
| 9    | 开放问题与决策点（让评审会重点讨论这个） | §8.2          |
| 10   | 风险与依赖                               | §8.3          |
| 附录 | 非功能要求、技术约束                     | §6 §7         |

**调用方式**：

1. 先在工作区生成一份 `spec-review-outline.md`，只包含上面 9-10 页的精炼内容
2. 调用 `pptx` skill，把这份 outline 转成 pptx
3. 输出 `spec-review.pptx`

**风格**：

- 每页只讲 1 件事，标题就是结论
- 用列表、表格、图，不要长段文字
- 「非目标」那页用红色或加粗强调——这是评审会最有价值的一页

---

## 多格式一键导出

用户说"导出所有格式"、"发给团队"、"准备一套" 时：

依次执行：

1. `spec.docx`（docx skill）
2. `spec.pdf`（基于 docx）
3. `spec-review.pptx`（pptx skill + 精炼大纲）

完成后给用户一个清单：

```
✅ spec.md          原始版（持续维护这份）
✅ spec.docx        Word 版（归档）
✅ spec.pdf         PDF 版（对外）
✅ spec-review.pptx 评审 PPT（10 页）
```

---

## 反模式

- ❌ 在 `spec-builder` 里实现导出逻辑（复用现有 skill）
- ❌ 把 PPT 做成每节一页（评审 PPT ≠ 文档目录）
- ❌ 自动加版本号（用户自己控制）
- ❌ 导出后删除 spec.md（**这是真相源，永远保留**）
