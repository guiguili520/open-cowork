# 范例：B2B 报价工具 PRD（片段）

> 这是一份"看起来像填好了"的 PRD 范例，给智能体对齐颗粒度和风格用。
> **不要把这里的内容直接搬到用户的 spec.md**——只参考写法。

---

## 1. 项目概述

- **一句话定位**：给 SaaS 销售用的报价单生成工具，1 分钟出标准报价。
- **目标用户**：负责 B 端付费转化的 SaaS 销售（不含市场、不含售后）。
- **核心价值**：把"配置→报价"从 45 分钟的 Excel 手工活，压到 5 分钟的下拉选择+一键导出。

**状态**：`confirmed`

---

## 3. 目标与非目标

### 3.1 目标

- G-001：单份标准报价生成时间 ≤ 5 分钟（当前 45 分钟）
- G-002：上线 3 个月内覆盖公司 80% 销售的日常报价场景

### 3.2 非目标

- NG-001：不做合同审批流程，对接现有 OA 审批
- NG-002：不做客户 CRM 功能，从现有 Salesforce 拉数据
- NG-003：不做多语言（首期只做简体中文）
- NG-004：不做移动端（销售都在电脑前出报价）

**状态**：`confirmed`

---

## 4. 用户故事（摘）

### U-001

- **角色**：一线销售
- **场景**：客户来询价，需要快速给出符合公司定价规则的报价
- **动机**：避免手工查表算价，避免报错被销售总监打回
- **验收标准**：
  - [ ] 选完产品 + 数量 + 折扣区间后，系统自动算出总价
  - [ ] 超出销售权限的折扣会触发审批提示，不能直接提交
  - [ ] 一次填写 ≤ 5 分钟

### U-003

- **角色**：销售总监
- **场景**：月底想看团队所有报价的状态分布
- **动机**：发现卡住的单子主动介入
- **验收标准**：
  - [ ] 仪表盘按"已发出/待审/已成交/已流失"分类
  - [ ] 能下钻到具体报价单
  - [ ] 数据延迟 ≤ 1 小时

**状态**：`confirmed`

---

## 5. 功能需求（摘）

### 5.2 报价模块

#### F-007 — 报价单 PDF 导出

- **输入**：报价单 ID
- **输出**：`/exports/quotation-{id}-{ts}.pdf`，HTTP 200 返回下载链接
- **主流程**：取数 → 模板渲染（公司模板）→ 加水印（公司 logo）→ 写盘 → 返回签名链接
- **异常分支**：
  - 报价单状态 = 锁定 → 返回 423 Locked
  - 模板缺失 → 返回 500 + 写告警日志
- **依赖**：模板服务、对象存储
- **溯源**：→ U-001

**状态**：`confirmed`

## 8. 里程碑与开放问题（摘）

### 8.1 里程碑

| 阶段     | 范围                                | 预计完成 |
| -------- | ----------------------------------- | -------- |
| M1 (MVP) | 报价创建、PDF 导出、基础权限        | T+8 周   |

### 8.2 开放问题

- Q-001：折扣审批层级——一级（直属经理）还是二级（经理 + 财务）？等业务侧 5 月 30 日前回复
- Q-002：是否支持外币报价？目前只有 1 个海外客户，先记下不实现
- Q-003：报价单模板的法务条款由哪个部门维护？

### 8.3 风险

- R-001：Salesforce 数据接口稳定性历史不好，可能影响 M2 进度
- R-002：销售习惯改变的阻力——历史上推过的工具用了 2 周就被弃用

**状态**：`confirmed`

## 范例使用要点

智能体在写用户的 spec.md 时：

1. **颗粒度参照**：每个 F-xxx / U-xxx 的篇幅约等于这里一条
2. **量化优先**：所有性能、目标、验收标准都要带数字或可二元判定
3. **溯源链路**：F-xxx 末尾标 → U-xxx，方便审稿时追溯
4. **非目标要狠**：哪怕用户没说，也要主动追问"不做什么"
5. **风格保留**：用户说"销售"就不要改成"销售人员"
